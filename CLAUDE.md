# CLAUDE.md – guidance for Claude Code

TaxPulse: multi-agent app for German tax advisors. Read `docs/SPEC.md` first; it is the source of truth for scope, agents, data model and roadmap.

## Layout
- `backend/app/` FastAPI. `config.py` settings from root `.env`; `models.py` SQLModel tables (spec §6); `routes/` one module per resource, mounted under `/api`; `seed.py` loads `data/demo/`.
- `backend/app/agents/` one module per agent (`profiler.py`, `analyst.py`, `matcher.py` with the free pre-filter, `explainer.py` (memo on accepted alerts), `writer.py` (one email draft per client)), `runner.py` (single entry point for LLM calls via CrewAI; `get_runner` returns it wrapped with the monthly budget check and retries of temporary API errors; swappable in tests through the `get_runner` dependency), `schemas.py` (agent outputs), `citations.py` (quote verification).
- `backend/app/sources/bmf.py` BMF 'Steuern' RSS feed ingestion (full text from attached PDF or page); HTTP client is the `http_client` dependency, mocked in tests. The BMF site usually answers software with a CAPTCHA: never bypass it. Instead the advisor passes it in their browser and clicks the "Send to TaxPulse" bookmarklet (`frontend/src/components/SendButton.tsx`), which posts the open feed to `POST /api/updates/receive-feed` (CORS allows only the BMF origins in `feed_sender_origins`).
- `backend/app/sources/bfh.py` Federal Fiscal Court feeds (decisions, press releases), open to software: read automatically by the weekly check and `POST /api/updates/fetch-bfh`.
- `backend/app/routes/dashboard.py` dashboard (KPIs, next steps, who to call), relevance matrix, live chain view (`/pipeline`) and the one-click chain run (`POST /pipeline/run`: Profiler → Analyst → Pre-filter + Matcher; stops before the advisor's review).
- `backend/app/quality.py` stability test (the Matcher re-scores the labelled demo pairs N times, nothing written to matches/alerts; results in `EvalBatch`), the Quality report, and `recover_interrupted` (start-up: runs left 'running' by a restart are marked failed). Routes in `routes/quality.py`.
- `backend/app/automation.py` the weekly check: a loop started in `main.py` (off when `SCHEDULER=false`, as in tests) runs `tick` every minute; when the weekly slot (local day and hour) has passed since `last_run_at`, it fetches the BMF feed, runs the chain and writes `Notification`s. Missed slots run at the next start-up. Routes in `routes/automation.py` (`/automation`, `/notifications`).
- `backend/app/replay.py` public demo (`DEMO_MODE=true`): `replay_runner` answers agent calls from `data/demo/replay.json` (exported with `python -m app.replay export <db>`), `reset_demo` restores the fresh demo. `main.py` blocks risky endpoints in demo mode (`DEMO_BLOCKED`), resets after idle time and serves the built frontend when `STATIC_DIR` is set. Deploy: `Dockerfile` + `render.yaml` (uses `backend/requirements-demo.txt`, no CrewAI).
- `backend/app/evaluation.py` scores stored matches against `data/demo/expected_matches.json` (also `GET /api/evaluation`).
- `backend/tests/` pytest; `conftest.py` provides a fake runner so tests never call the API; tests use a temporary SQLite DB via env vars set at the top of the test file.
- `frontend/src/` React + TS + Tailwind v4. `api.ts` typed API client; `pages/` one file per route; `components/ui.tsx` shared UI. Vite proxies `/api` to `localhost:8000`.
- `data/demo/` fictional data rooms (PDF, generated by `build_data_rooms.py`), `updates.json`, `expected_matches.json` (ground truth for agent evaluation).

## Commands
- Backend: `cd backend && .venv/Scripts/python -m uvicorn app.main:app --reload` (Windows) · tests: `.venv/Scripts/python -m pytest -q`
- Frontend: `cd frontend && npm run dev` · type check + build: `npm run build`
- Windows helpers at repo root: `setup.bat`, `start.bat`, `test.bat`

## Conventions
- Python 3.13 (CrewAI requires < 3.14). UI text and agent outputs in English.
- Every agent output is a Pydantic model; every client fact carries a source (document + page).
- Log every agent call in `AgentRun` (model, tokens, cost, duration).
- Never auto-send emails; drafts need advisor approval (edit resets approval; 'sent' only after 'approved').
- Demo data is fictional and must stay labelled as such.
- Design tokens live in `frontend/src/index.css`: the "Sage Garden" theme by @serafimcloud (21st.dev), copied as published (light in `:root`, dark in `.dark`, exposed via `@theme inline`, e.g. `bg-primary`, `text-muted-foreground`; note its `--spacing: 0.23rem`). The app's own colour names are mapped onto it (`paper`=background, `sheet`=card, `ink`=foreground, `slate`=muted-foreground, `rule`=border, `brand`=sage primary deepened for text, `heat`=earthy ochre reserved for relevance/alerts, `ok`=green for success, `danger`=destructive red for real problems only; in-progress notes use `tp-busy` on `bg-muted`). Dark mode = `.dark` on `<html>`, toggled in the top bar, remembered in localStorage `taxpulse.theme` (applied before paint by a script in `index.html`). Fonts: Antic (UI), Signifier with Georgia fallback (headings, `font-serif`; Signifier is not on Google Fonts, so Georgia shows unless it is installed), JetBrains Mono. Older class names (`.tp-chrome` cards, `.tp-rail` sidebar, `.tp-btn-primary/-quiet` with hover shine and click ripple, `.tp-chrome-dark` forest-green lead card) are kept but restyled. `components/LiquidMetalButton.tsx` (WebGL, `@paper-design/shaders`) is the one showcase button (agent chain); use it at most once per page. Ctrl/Cmd+K jump palette (`components/CommandPalette.tsx`); the Briefing page shows the relevance radar.
- Add or update tests with every backend change; keep `npm run build` passing.
